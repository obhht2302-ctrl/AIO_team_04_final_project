## 1. 개요

**한 줄 정의:** 퀴즐렛식 학습 세트와 자녀보호 기능을 결합해, 초중학생 자녀의 학습 커리큘럼과 안전 관리를 한 번에 맡길 수 있는 서비스.

| 항목 | 내용 |
| --- | --- |
| 대상 | 초·중학생 자녀와 학부모 |
| 형태 | Flutter 앱 2종(학부모용·자녀용), App Store·Google Play 정식 출시 |
| 요금 | 무료 + 사용량 한도 |
| 차별점 | 고정 영단어가 아니라 **"우리 아이 자료로 만든 커리큘럼 + 학원 일정 + 이행도 통계"** |

**경쟁·유사 서비스:** "퀴즈 풀면 잠금 해제"는 이미 존재한다(놀려면공부 — 영단어 퀴즈로 자유시간 획득 + 부모 대시보드, 스카이홈 — 영어 퀴즈 잠금 해제 + 위치 추적). 따라서 차별점은 **자료 기반 커리큘럼**과 **검수된 문항 품질**에 둔다.

**서비스 핵심 흐름**

```
학부모 앱 ─┐
           ├─ ① 자료 업로드(PDF·사진·CSV)
서버·AI ───┼─ ② 문항 생성·검수
           ├─ ③ 부모 검수·승인 → 커리큘럼 설정
           ├─ ④ 자녀 일일 미션 풀이(오프라인 가능)
           ├─ ⑤ 미션 완료 → 앱 잠금 해제
           ├─ ⑥ 이행 집계 → 주간 AI 리포트
           └─ ⑦ 통계·리포트 도착 알림
자녀 앱 ──┘
           ※ 학원 도착·출발 감지(지오펜스)는 학습 순환과 별도로 돈다
```

## 3. 사용자와 계정 구조

### 3.1 가입과 연결 흐름

1. 학부모 앱에서 Google 또는 Apple로 로그인
2. 휴대전화 번호 입력 → 문자 인증번호 확인
3. 자녀 프로필 입력: 별명, 출생 연월, 학년
4. **법정대리인 동의**(개인정보 수집·이용, 생성형 AI 고지) → 프로필과 동의를 함께 저장하고, 동의가 확인됐다는 문자를 부모 휴대전화로 발송
5. 연결 코드 발급: 숫자 6자리, 10분 유효, 1회용, 5회 틀리면 폐기
6. 자녀 기기에 자녀 앱 설치 → 코드 입력 → 기기가 자녀 프로필에 연결
7. 자녀 기기에서 부모와 함께 "가족 약속" 진행(3.3) + OS 권한 설정

> **학부모 앱 ↔ Supabase ↔ FastAPI ↔ 자녀 앱** 순서로 요청이 오간다. 실선은 요청, 점선은 서버가 부모 휴대전화로 보내는 문자다. **⑦(가족 약속·권한)은 MVP 뒤 1.0에 들어간다.**

### 3.2 계정 종류

| 구분 | 인증 | 권한 |
| --- | --- | --- |
| 학부모 | 소셜 로그인 + 문자 확인 | 세트 검수, 커리큘럼·차단 정책·장소 설정, 통계 열람, 해제 요청 승인 |
| 자녀(만 14세 미만) | 계정 없음. 연결 코드로 기기 연결 | 미션 풀이, 체크인, 해제 요청 |
| 자녀(만 14세 이상) | 위와 같음 | 위 + 본인이 커리큘럼 편성. 부모는 열람 |

- 자녀에게서 **이메일·전화번호를 받지 않는다.**
- 자녀 기기는 Supabase **익명 세션**으로 시작하고, 서버가 연결 코드를 확인해 그 세션을 자녀 프로필에 묶는다.
- 앱을 다시 설치하면 다시 연결한다.
- 두 번째 보호자 초대는 1.0 범위 밖. **데이터 모델만 보호자 여러 명을 허용**해 둔다.

### 3.3 가족 약속 (동의)

자녀 기기에서 부모와 자녀가 함께 보는 화면. **항목별로 부모 확인과 자녀 확인을 따로 받는다.**

- **위치:** 어떤 장소에서 알림이 가는지, 누가 받는지, **이동 경로는 모으지 않는다**는 점
- **앱 사용 제한:** 차단할 앱, 시간대, 미션 조건, 해제 요청 방법
- 동의 기록은 **주체(부모·자녀), 문서 버전, 시각**과 함께 저장한다.
- 자녀는 자녀 앱에서 위치 공유를 끌 수 있고, 끄면 부모에게 알림이 간다(동의 철회).
- 만 14세가 되는 달에 "커리큘럼 결정권이 본인에게 넘어간다"는 안내와 함께 **동의를 다시 받는다.**

## 4. 기능 명세

### 4.1 학습 세트

- **입력:** PDF, 사진, CSV(용어·뜻 2열)
- **흐름:** 업로드 → AI 파이프라인(5장) → **부모 검수 화면**(문항별 승인·수정·삭제) → **승인된 문항만** 자녀에게 배포
- **문항 유형:** 카드, 객관식(4지), 빈칸, 철자
- **기본 팩:** 필수 영단어, 한자, 국어 어휘, 영문법. 팀이 미리 생성·검수해 DB에 넣어 둔다. **원본 목록의 출처와 이용 조건은 10.2 출처 표에서 확인**한다.
- **사용량 한도(초안값):** 가정당 월 20건, 하루 5건, 건당 PDF 30쪽·사진 10장·20MB. 값은 테이블로 관리하고, **2주차에 문항 생성 1건당 비용을 실측해 확정**한다.

### 4.2 커리큘럼

- **입력:** 세트, 기간, 하루 최대 분량. 학원 일정이 많은 요일은 분량을 줄인다.
- **배분:** 규칙 기반(총 문항 ÷ 가능 일수, 요일 가중치). **LLM은 단원 순서와 묶음만 제안**한다.
- **간격 반복:** 5단계 상자(1·2·4·7·15일). 틀리면 1단계로 돌아간다.
- **일일 미션:** 신규 + 복습 문항. 완료 조건은 **"전부 풀이 + 틀린 문항 다시 풀이 1회"**.
- **밀린 미션:** 다음 날로 넘기되, 하루 최대 분량을 넘는 몫은 남은 기간에 다시 나눈다.
- 만 14세 이상은 본인이 편성하고 부모는 열람한다.

### 4.3 앱 사용 관리

- **정책 2가지:** 약속 시간대 차단(요일·시간), 오늘 미션 완료 전까지 차단
- **항상 허용:** 전화, 문자, 부모 연락, 자녀 앱 자체
- **차단 앱 선택:** 두 OS 모두 **자녀 기기에서 부모와 함께** 고른다. iOS가 시스템 선택 화면만 허용하므로 Android도 같은 흐름으로 맞추고, **설치 앱 목록은 서버로 보내지 않는다.** 부모 앱에서는 시간대와 조건만 바꾼다.
- **해제 요청:** 자녀가 사유와 시간(15·30·60분)을 골라 요청 → 부모에게 푸시 → 승인하면 그 시간만 해제
- **오프라인 동작:** 정책과 7일치 미션을 자녀 기기에 저장한다. 미션 완료와 잠금 해제는 **기기 안의 규칙 엔진**이 판정하고 나중에 서버와 맞춘다.
- **우회 감지:** 권한이 꺼지거나(접근성, Screen Time 승인) 기기 신호가 24시간 끊기면 부모에게 알린다.

**잠금 상태 전이**

```
차단 중 ──(미션 완료·약속 시간대 종료)──→ 차단 앱 사용 가능
       ──(부모가 해제 요청 승인)──────→ 임시 해제 15·30·60분
임시 해제 ──(허용 시간 만료)──────────→ 차단 중
차단 앱 사용 가능 ──(새 날 미션 시작·약속 시간대 시작)──→ 차단 중
```

> **판정은 자녀 기기 안의 규칙 엔진이 내린다**(네트워크 없이도 동작). 전화·문자·부모 연락·자녀 앱은 항상 허용.

### 4.4 학원·장소 관리

- **주간 일정표:** 학원명, 요일·시간, 장소 연결
- **등록 장소:** 이름, 주소 검색 → 좌표, 반경(기본 150m, 100~300m). 가정당 10곳
- **자동 감지:** OS 지오펜스로 진입·이탈만 감지해 부모에게 푸시. **서버에는 장소 ID, 종류, 시각만** 보낸다. **좌표 원본과 이동 경로는 기기 밖으로 나가지 않는다.**
- OS 특성상 알림이 몇 분 늦을 수 있다.
- **체크인:** 자녀가 버튼을 누르면 현재 위치를 한 번 측정해 등록 장소 반경 안일 때만 인정. 판정은 기기에서 하고 **서버에는 결과와 정확도만** 보낸다. 자동 감지가 놓쳤을 때의 보조 수단.
- 정확도가 나쁘면(오차 100m 초과) 다시 시도하도록 안내. Android 모의 위치는 무효 처리.
- **미도착 알림:** 수업 시작 10분 뒤까지 진입도 체크인도 없으면 부모에게 알림.
- **자녀에게 통보:** 부모에게 위치 알림이 갈 때마다 자녀 앱에도 기록을 남긴다("수학학원 도착을 엄마에게 알렸어요").

**위치 정보의 경계**

| 구분 | 기기에서 끝남 | 서버로 감 |
| --- | --- | --- |
| 좌표 원본 | ✅ | ❌ |
| 이동 경로 | ✅ (수집하지 않음) | ❌ |
| 지오펜스·체크인 판정 | ✅ | ❌ |
| 장소 ID·종류·시각·정확도 | — | ✅ |
| 도착 기록·제공 사실 | — | ✅ |

### 4.5 통계·리포트

- 일·주·월·학기 이행률, 연속 달성일, 취약 단원(오답률 상위), 학원 도착 기록
- **주간 AI 리포트:** 매주 일요일 저녁에 생성해 학부모 앱과 푸시로 전달. **LLM에는 집계 수치만** 넘긴다(자녀 이름·좌표 제외).
- 자연어 질의 응답은 후순위. 시간이 남으면 주간 리포트 범위 안에서만 연다.

### 4.6 MVP 범위

먼저 만들어 검증하는 범위다. **"부모가 올린 자료가 검수된 문항이 되고, 자녀가 그것을 그날의 미션으로 끝까지 푸는가"**에 답하는 것만 넣었다.

| 영역 | MVP | 그 뒤(1.0) |
| --- | --- | --- |
| 가입·연결 | 소셜 로그인, 문자 확인, 자녀 프로필과 동의, 연결 코드 | 가족 약속(위치·앱 제한 동의) |
| 학습 세트 | PDF·CSV 업로드, 문항 생성과 검수, 부모 검수, 기본 팩 1종 | 사진 업로드, 나머지 기본 팩 |
| 커리큘럼 | 기간·하루 분량·쉬는 요일로 균등 배분, 일일 미션, 간격 반복 | 학원 일정 반영, 밀린 미션 재배분, 만 14세 이상 본인 편성 |
| 앱 사용 관리 | 없음 | 전부 |
| 학원·장소 | 없음 | 전부 |
| 통계 | 학부모 홈의 오늘 현황 | 통계 화면, 주간 AI 리포트 |

**차단과 위치를 뺀 이유:** 외부 승인에 걸려 있어 일정을 팀이 정할 수 없고, 위 질문에 답하는 데 필요하지 않다.

## 5. AI 파이프라인

### 5.1 단계와 제공자

| 단계 | 하는 일 | 제공자(초안) |
| --- | --- | --- |
| 1. 파싱 | PDF·사진을 읽어 단원·개념·용어로 구조화 | Gemini (문서·이미지 직접 입력) |
| 2. 커리큘럼 설계 | 단원 순서와 묶음 제안. 날짜 배분은 규칙 | 소형 모델 |
| 3. 문항 생성 | 유형별 문제 생성. 문항마다 **원문 근거(쪽, 인용문)** 첨부 | OpenAI (구조화 출력) |
| 4. 검수 | 원문과 대조해 정답 검증, 보기 중복·모호성, 학년 수준, 부적절 표현 | Gemini (생성과 다른 제공자로 교차 검증) |
| 5. 적응 | 오답 패턴으로 재출제와 순서 조정 | 규칙 + 소형 모델 |
| 6. 리포트 | 학부모용 주간 요약 | 소형 모델 |

- 모델 ID는 **설정값으로 분리**하고 1주차에 확정한다. 제공자는 **어댑터 계층** 뒤에 둔다.
- 생성과 검수를 서로 다른 제공자에 맡겨, 같은 실수가 그대로 통과하는 일을 줄인다.

### 5.2 LangGraph 구성

- **세트 생성 그래프:** 파싱 → 단원 계획 → 생성 → 검수 → (불합격이면 재생성, 최대 2회) → 저장(부모 검수 대기). **두 번 불합격한 문항은 버린다.**
- **주간 그래프:** 적응 → 리포트
- **실행은 비동기.** 업로드하면 작업 행이 생기고, 워커가 단계별 상태를 DB에 기록하며, 학부모 앱이 Supabase Realtime으로 진행 상황을 본다.
- **1.0의 작업 큐는 Postgres 테이블(`FOR UPDATE SKIP LOCKED`) + 워커 1개.** **Redis나 Celery는 쓰지 않는다.**

### 5.3 안전장치

- LLM에 **자녀 이름이나 식별자를 보내지 않는다.**
- Google AI Studio는 **유료 등급**을 쓴다(무료 등급은 입력이 제품 개선에 쓰일 수 있음 — 확인 필요, 10.1).
- **잠금 해제 판정은 LLM이 아니라 규칙 엔진**으로 둔다. 오판 한 번이 신뢰를 깨는 기능이기 때문.
- **가드레일:** 금지 표현(복용·투약 단정 등), 개인정보 노출, 프롬프트 주입 차단. 각 항목에 **테스트 케이스 3개 이상**을 둔다.

### 5.4 평가 — **두 트랙을 분리한다**

| 트랙 | 목적 | 자료 | 산출물 | 담당 |
| --- | --- | --- | --- | --- |
| **A. 내부 검수 평가** | 문항 정답률·검수 품질 | 팀이 만든 샘플 **20건** | 정답률(목표 95%) | 심환석 |
| **B. BFCL 원본 평가** | 도구 호출·에이전트 능력 | **BFCL 원본 30문항** | 문항별 통과/실패 | 심환석 |

> 두 평가는 **목적·자료·결과가 다르므로 표를 합치지 않는다.** WBS 3.2.5(내부) / 3.2.6(BFCL).

## 6. 시스템 구성

### 6.1 전체 구조

| 계층 | 구성 |
| --- | --- |
| 학부모 앱 | 업로드·검수·설정·통계 |
| 자녀 앱 | 미션 풀이·규칙 엔진. 네이티브(Swift·Kotlin)로 앱 차단·지오펜스·체크인 |
| Supabase(서울) | Auth(로그인·자녀 익명 세션), Postgres + RLS, Storage(업로드 원본), Realtime(진행 상태·해제 요청) |
| FastAPI(EC2 서울) | LangGraph 파이프라인, 스케줄러(미션·미도착·리포트), 발송(푸시·문자) |
| 외부 | Google·Apple 로그인, OpenAI, Gemini, SMS 발송사, FCM |

**경계 원칙:** RLS로 막을 수 있는 읽기·쓰기는 앱이 **Supabase에 직접** 한다. 비밀 키·LLM·외부 발송이 필요한 일만 **FastAPI를 거친다.**

### 6.2 역할 분담

| 구성 요소 | 맡는 일 |
| --- | --- |
| Supabase | 인증, DB, 파일 저장, 실시간 구독. RLS로 가족 단위 격리 |
| FastAPI | AI 파이프라인, 연결 코드, 문자 발송, 푸시 발송, 스케줄 작업, 사용량 한도 집행 |
| 자녀 앱 | 미션 풀이, 규칙 엔진(잠금 판정), 차단, 지오펜스. 오프라인에서도 동작 |
| 학부모 앱 | 업로드, 검수, 설정, 통계. 네이티브 권한 없음 |
| **관리자 웹** | 문항·사용자·신고 대응 운영 화면 (React, 내부용) |
| **교육용 웹 앱** | 학부모용 학습 현황·리포트 열람 (Flutter Web 또는 React) |

### 6.3 Flutter 구성

- **코드베이스 하나, 앱 두 개.** 무거운 권한과 심사 부담을 자녀 앱에만 몰아두면 학부모 앱은 먼저 통과시킬 수 있다.
- **저장소 구조(초안)**

```
apps/parent/        학부모 앱
apps/child/         자녀 앱 (ios/, android/ 에 네이티브 코드)
packages/shared/    모델, Supabase 클라이언트, 규칙 엔진, 공통 UI
server/             FastAPI (api, pipeline, providers, jobs, notify, agents)
supabase/           마이그레이션, RLS 테스트
web-admin/          관리자 웹 (React)
web-parent/         교육용 웹 앱 (Flutter Web)
site/               약관·처리방침·지원 페이지 (정적)
docs/               결정 기록, 계획, 산출물
```

- **차단·위치는 빌드 옵션으로 분리한다.** 권한은 선언만 해도 심사 대상이라 원격 설정으로는 끌 수 없다. **심사에서 막히면 해당 권한을 뺀 빌드를 바로 낼 수 있어야 한다**(9.3).
- 웹이 필요해지면 학부모 앱을 Flutter Web으로 빌드해 대응한다.

### 6.4 자녀 앱 네이티브 영역

**iOS 차단**
- FamilyControls(권한), ManagedSettings(차단), DeviceActivity(시간대)
- 확장 타깃 3개: Device Activity Monitor, Shield Configuration, Shield Action. App Group으로 정책 공유
- 번들 ID: `…child`, `…child.monitor`, `…child.shield`, `…child.shieldaction`
- Flutter 플러그인은 0.0.x대 초기 버전이라 **의존하지 않고**, 필요한 호출만 채널로 직접 쓴다.
- 권한 모드: `.child`가 기본. 자녀 기기가 가족 공유의 자녀 Apple 계정으로 로그인돼 있어야 하고 부모가 그 자리에서 승인한다. 조건이 안 되는 가정은 `.individual`로 받되, 자녀가 설정에서 끌 수 있으므로 **꺼짐을 감지해 부모에게 알린다.**
- 해제 승인: 부모가 승인하면 자녀가 알림을 눌러 앱이 열릴 때 해제된다. 백그라운드에서 바로 풀 수 있는지는 **실기기 PoC에서 확인한 뒤 정한다**(WBS 4.0.1).
- Screen Time API는 **시뮬레이터에서 동작하지 않아 실기기가 필요**하다.

**Android 차단**
- 접근성 서비스로 앞에 뜬 앱을 감지하고, 차단 대상이면 전체 화면 차단 화면을 띄운다.
- 설치 앱 목록은 **실행 가능한 앱만** 조회한다(`QUERY_ALL_PACKAGES`는 별도 심사 대상이라 쓰지 않음).
- 재부팅 뒤 자동 시작, 배터리 최적화 예외 안내.

**위치(두 OS 공통)**
- iOS는 지역 모니터링(앱당 최대 20곳), Android는 Geofencing API(앱당 최대 100곳). **재부팅하면 다시 등록.**
- 자녀 기기에 위치 "항상 허용"이 필요하다.
- 플러그인 품질을 1주차에 확인하고, 불안하면 네이티브로 직접 구현한다.

### 6.5 인프라와 배포

| 항목 | 내용 |
| --- | --- |
| Supabase | 호스팅형, **서울 리전**. CLI 마이그레이션, pgTAP으로 RLS 테스트 |
| EC2 | 서울 리전, 작은 인스턴스 1대로 시작. **Docker Compose + nginx + certbot(자동 TLS)**, 고정 IP와 도메인 |
| 배포 | GitHub Actions가 이미지를 빌드하고 EC2가 받아 재시작. **배포용 IAM 권한을 따로 만들고 루트 자격 증명은 쓰지 않는다** |
| 비밀 값 | 서버의 `.env`에만 두고 저장소에는 **`.env.example`만** 둔다. ⚠️ **`.env` 값 뒤에 인라인 `#` 주석을 쓰지 않는다**(Compose가 주석을 제거하지 않아 값이 오염됨) |
| 푸시 | FCM. 자녀 앱에서는 Firebase Analytics를 끈다(8.2) |
| 앱 배포 | iOS는 `flutter build ipa` 후 App Store Connect API 업로드, TestFlight. Android는 내부 테스트 트랙 |

> **정정:** v0.3의 **Caddy**를 **nginx + certbot**으로 바꾼다(WBS 2.2.6과 통일). 이유: 팀이 이미 nginx 경험이 있고, 리버스 프록시 설정을 직접 통제하기 위해.

## 7. 데이터 모델과 API

### 7.1 핵심 테이블

| 영역 | 테이블 |
| --- | --- |
| 가족 | `families`, `guardians`, `children`, `child_devices`, `pairing_codes`, `phone_verifications`, `consents` |
| 학습 | `study_sets`, `items`, `generation_jobs`, `curricula`, `curriculum_items`, `daily_missions`, `mission_items`, `attempts`, `review_states` |
| 차단 | `block_policies`, `unlock_requests` |
| 장소 | `places`, `schedules`, `place_events`, `location_disclosure_logs` |
| 알림 | `push_tokens` |
| 통계 | `weekly_reports`, `usage_counters`, `usage_limits` |
| 운영 | `admin_users`, `audit_logs`, `agent_runs` |

- `children`: 별명, 출생 연월, 학년, 관리 방식(보호자 관리·본인 관리)
- `items`: 유형, 문제, 정답, 보기, **원문 근거**, 검수 상태(AI), 승인 상태(부모)
- `place_events`: 장소 ID, 종류(진입·이탈·체크인), 출처(자동·수동), 정확도, 시각. **좌표는 저장하지 않는다.**
- `location_disclosure_logs`: 누구에게, 언제, 무슨 목적으로 알렸는지. **위치정보 제공 사실 확인자료**
- `agent_runs`: 에이전트 실행 ID, 단계, 제공자·모델, 토큰, 소요, 결과, 폴백 여부 — **Auto-Healing 증거**

### 7.2 접근 제어

- 가족 범위 테이블은 가족 ID로, 자녀 범위 테이블은 자녀 ID로 격리한다. 보호자는 자기 가족 전체, 자녀 기기는 연결된 자녀의 데이터만.
- 자녀 기기는 미션·문항을 읽고 풀이·이벤트를 쓴다. **정책·장소·커리큘럼(만 14세 미만)은 바꿀 수 없다.**
- 업로드 원본은 비공개 버킷에 두고 **서명 URL로만** 연다.

### 7.3 FastAPI 엔드포인트

| 메서드·경로 | 호출 | 하는 일 | 시점 |

- 스케줄 작업(1.0): 미도착 알림(1분 간격), 주간 리포트(일요일 저녁), 기기 신호 점검

## 8. 규제·심사 리스크

> **이 장은 1차 조사다.** 각 항목의 확인 상태와 근거 원문은 **10.1 확인 상태 표**에 따로 관리한다. 이 문서의 서술은 **적합성 확인이 아니다.**

### 8.1 법적 사항

**위치기반서비스업 신고**
- 개인위치정보를 다루면 신고 대상. 미신고 운영 시 **3년 이하 징역 또는 3천만 원 이하 벌금**(확인 필요).
- 수리에 최대 2주 소요.
- 신고는 진행 중이다. "자녀의 등록 장소 진입·이탈을 보호자에게 알리는 서비스"가 신고 내용에 포함되는지, 추가·변경 신고가 필요한지 **방송미디어통신위원회(옛 방통위)에 확인**한다(10.1).
- 방미통위는 2026년 4월 위치정보법 위반 사업자 373곳을 제재했다. **수리 전에는 위치 기능을 뺀 빌드로 출시**한다(9.3).

**자녀 위치의 이중 동의**
- 자녀 안심 앱 5곳이 아동 본인 동의 없이 부모에게 위치를 제공했다가 시정명령·과태료 처분.
- Google 패밀리링크 소송에서 1심·항소심 모두 **부모 동의만으로는 부족**하다고 판단.
- 등하교 앱은 예외로 본 판결도 있어 해석이 갈림 → **가족 약속 화면에서 부모와 자녀 둘 다 동의**받는다.
- 8세 이하 아동은 보호의무자 동의 특례가 있음(위치정보법 제26조, 확인 필요). 초등 저학년이 해당할 수 있다.

**위치정보 사업자 의무** (모두 확인 필요)
- 제3자(부모)에게 제공할 때 자녀에게 제공받는 사람·일시·목적을 알릴 것 → 4.4의 자녀 통보로 대응
- 수집·이용·제공 사실 확인자료를 자동으로 기록·보존할 것 → `location_disclosure_logs`. 보존 기간은 원문 확인
- 위치기반서비스 이용약관, 위치정보관리책임자 지정 — 새로 작성한다

**아동 개인정보**
- 만 14세 미만은 법정대리인 동의와 그 확인이 필요하다. 동의를 확인했다는 사실을 법정대리인 휴대전화 문자로 알리는 방식을 쓴다(개인정보 보호법 시행령 제17조의2).
- 자녀에게서 받는 정보는 **별명, 출생 연월, 학년**으로 최소화한다.
- 처리 위탁·국외 이전: Supabase, OpenAI, Google, Firebase, SMS 발송사를 처리방침에 적는다.

**AI 기본법:** 생성형 AI 기반 서비스라는 사실을 이용자에게 사전 고지. 과태료는 1년 계도기간.

**저작권 — 업로드 자료의 이용 조건**
- 업로드 자료로 만든 세트는 **가족 안에서만 사용**, 공개 공유 기능 없음.
- ⚠️ **"가족 안에서 사용"이라는 문구만으로 이용 조건 확인이 끝나지 않는다.** 자료별로 **이용조건·AI 입력 허용 여부·변형(문항 생성) 범위·배포 범위**를 확인해야 한다(10.2).
- 기본 팩의 원본 목록도 출처와 이용 조건을 확인한 자료만 쓴다.

**공개 문서:** 개인정보처리방침, 이용약관, 위치기반서비스 이용약관, 지원 페이지의 URL이 스토어 제출에 필요하다. 정적 페이지로 호스팅한다.
