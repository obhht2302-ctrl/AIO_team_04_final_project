## 3. 앱 구조 결정 — **B안 확정 (앱 2종)**

| 항목 | A안: 단일 앱 + 역할 선택 | **B안: 앱 2종 (확정)** |
| --- | --- | --- |
| 사용성 | 설치 1회, 편함 | 부모·자녀 각자 설치 |
| 권한·심사 | 자녀용 무거운 권한이 **부모 앱에도 선언** → 부모 앱 심사 지연 | 부모 앱은 권한 없음 → **먼저 통과 가능** |
| 차단 구현 | iOS FamilyControls가 앱 단위 → 한 앱에서 역할 분기 복잡 | 자녀 앱에만 몰아두면 단순 |
| 스토어 정책 | 아동 대상 앱에 보호자 확인 단계 필요 → 단일 앱이 더 엄격 | 분리 시 정책 대응 명확 |
| 데이터 | 계정 1개에 역할 필드 | 기기-자녀 연결 구조 명확 |
| **판정** | ❌ 탈락 | ✅ **채택 (2026-11-12)** |

> **결정 내용**: Flutter 코드베이스 하나에서 **빌드 타깃만 2개**로 나누고, 공통 UI·로직은 `packages/shared` 로 공유. 사용자는 "같은 앱"처럼 느낀다. 번들 ID `com.shs5029.haru.parent` / `.child`.

## 6. 기능 상세

### FR-ACC-001 역할 선택 및 로그인

| 항목 | 내용 |
| --- | --- |
| 액터 | 학부모 |
| 시점 | MVP |
| 목적 | 앱 진입 시 역할을 선택하고 소셜 계정으로 로그인한다 |
| 입력 | 로그인 제공자(Google/Apple), 역할 선택(학부모/자녀) |
| 처리 | Supabase Auth 세션 발급 → 역할에 따라 홈 분기. 자녀는 **익명 세션** |
| 출력 | 인증 토큰, 역할별 초기 화면 |
| 예외 | 미성년 자녀가 학부모 역할 선택 시 → 연결 코드 안내로 유도 |
| 인수 조건 | ① 로그인 후 3초 안에 역할별 홈이 표시된다 ② 자녀 세션은 이메일·전화번호를 저장하지 않는다 |
| 화면 | P-01 로그인, C-01 시작 |

### FR-ACC-002 자녀 프로필·법정대리인 동의

| 항목 | 내용 |
| --- | --- |
| 목적 | 자녀 정보를 **최소 수집**하고 법정대리인 동의를 기록한다 |
| 입력 | 별명, 출생 연월, 학년, 동의 체크 |
| 처리 | 동의 기록 저장(주체·문서버전·시각) → **부모 휴대전화로 동의 확인 문자 발송** |
| 출력 | 자녀 프로필, 동의 레코드 |
| 예외 | 동의 미체크 시 저장 불가 |
| 인수 조건 | ① 이메일·전화번호 입력란이 존재하지 않는다 ② 동의 확인 문자 발송이 5초 내 접수된다 |
| 근거 | 개인정보 보호법 시행령 제17조의2 |
| 화면 | P-03 자녀 등록 |

### FR-PAIR-001 연결 코드로 기기 연결

| 항목 | 내용 |
| --- | --- |
| 목적 | 부모 계정과 자녀 기기를 안전하게 연결한다 |
| 입력 | 학부모: 발급 요청 / 자녀: 6자리 코드 |
| 처리 | 코드 발급(**6자리·10분·1회용·5회 실패 시 폐기**) → 자녀 기기 익명 세션을 자녀 프로필에 귀속 |
| 출력 | 연결된 기기, 세션 |
| 예외 | 만료 `PAIRING_EXPIRED` / 사용됨 `PAIRING_ALREADY_USED` / 5회 초과 `PAIRING_LOCKED` |
| 인수 조건 | ① 두 실기기에서 가입~연결이 **3분 내** 완료된다 ② 재설치 시 재연결된다 |
| 화면 | P-04 코드 발급, C-02 코드 입력 |

### FR-SET-001 학습 자료 업로드

| 항목 | 내용 |
| --- | --- |
| 목적 | 부모가 가진 자료를 학습 세트로 만든다 |
| 입력 | PDF, CSV(용어·뜻 2열) |
| 처리 | 비공개 버킷 업로드(서명 URL) → `generation_jobs` 생성 |
| 제한 | **가정당 월 20건 / 하루 5건 / 건당 30쪽·20MB** (설정값) |
| 예외 | 한도 초과 `USAGE_LIMIT_EXCEEDED` / 형식 오류 `INVALID_INPUT` |
| 인수 조건 | ① 30쪽 PDF 업로드가 10초 내 완료된다 ② 한도 초과 시 사유가 표시된다 |
| 화면 | P-05 자료 업로드 |

### FR-SET-002 AI 문항 생성

| 항목 | 내용 |
| --- | --- |
| 액터 | 시스템(AI) |
| 목적 | 자료를 문항으로 변환한다 |
| 처리 | 파싱 → 단원 계획 → 생성 → **검수(다른 제공자)** → 불합격 시 **재생성 최대 2회** → 폐기 |
| 출력 | 문항(유형·문제·정답·보기·**원문 근거**) + 검수 상태 |
| 유형 | 카드, 객관식(4지), 빈칸, 철자, **단답식** |
| 예외 | 제공자 장애 `LLM_PROVIDER_DOWN` → 재시도 후 실패 표시 |
| 인수 조건 | ① 30쪽 기준 **3분 내** 검수 대기 상태가 된다 ② 모든 문항에 원문 근거가 붙는다 ③ **내부 평가셋 20건**에서 정답률 **95% 이상** ④ **BFCL 원본 30문항**은 별도 트랙으로 기록한다(10.3) |
| 화면 | P-05 진행률 |

### FR-SET-003 부모 문항 검수·승인

| 항목 | 내용 |
| --- | --- |
| 목적 | 자녀에게 가기 전 **부모가 승인**한다 |
| 입력 | 문항별 승인 / 수정 / 삭제 |
| 처리 | 승인된 문항만 배포. 수정 시 이력 저장 |
| 인수 조건 | ① 승인하지 않은 문항은 자녀 조회가 **불가**하다 ② 문항 20개 검수가 **5분 내** 가능하다 |
| 화면 | P-06 문항 검수 |

### 과제 요구 산출물 — FR-AI / FR-WEB

> 교강사 지적(11/14): "단일 에이전트·협업·자기 성찰·가드레일·Auto-Healing 산출물의 **작업 위치**가 보여야 한다."
> 아래 5개는 **FR-SET-002(문항 생성) 위에 얹히는 설계·검증 기능**이며, WBS **3.7.1~3.7.5** 와 1:1로 대응한다.
